# 交互式HTML产品原型生成

根据产品需求，生成完整的、可直接运行的单文件HTML产品原型。

## 核心工作流程

1. **盘点功能** - 区分全局通用组件与页面核心功能区，先建立页面级功能清单
2. **理解需求** - 明确每个核心功能区的组件、字段、操作和数据逻辑
3. **设计布局** - 规划左侧界面元素与右侧说明文档的对应关系
4. **编写代码** - 生成符合所有技术规范的完整HTML文件
5. **验证检查** - 确保所有连线正确、功能说明无遗漏、交互完整、响应式正常

## 功能说明建模规范（强制执行）

### 先建立功能清单

在编写页面前，必须按下面两层拆分需求，并以此作为右侧说明区的来源：

1. **全局通用组件**：跨多个页面复用的能力，例如主导航、全局搜索、消息提醒、账号/角色切换。
2. **页面核心功能区**：只属于当前页面，或者虽有相似形态但承载不同业务逻辑的区域，例如看板筛选与图表、数据中心任务表、对话的会话历史与交付物预览。

不得把一个页面概括成一张笼统说明卡。每个页面至少识别 2 个核心功能区；复杂页面按实际结构拆分，不设上限。

### 全局通用组件只说明一次

- 通用组件在原型中只创建一组说明卡，并放在首次出现的位置或独立的“全局功能”说明组。
- 后续页面不得重复同一段说明，也不得为相同菜单、角色信息、通知等重复绘制连线。
- 页面说明中如确实依赖全局能力，只写简短引用，例如“使用全局角色权限范围”，不要复制全量描述。
- 当用户切换页面时，全局说明保持稳定；只更新当前页面的核心功能区说明和对应连线。

### 页面核心功能区的说明模板

每个核心功能区必须逐项写出下列信息。没有的项要明确写“当前原型未实现”，不得凭空补充业务规则：

| 信息项 | 必须说明的内容 |
| --- | --- |
| 组件与字段 | 区域内的组件名称、关键字段/列/筛选项、状态标签、按钮或入口。表格必须说明主要列；表单必须说明主要输入项与默认值。 |
| 操作逻辑 | 用户可执行的点击、筛选、切换、提交、查看、编辑、删除、下载等操作，以及操作后的界面状态变化、禁用条件或弹窗。 |
| 数据逻辑 | 数据来源或当前原型数据、筛选/排序/聚合/联动规则、状态更新、计算口径和空状态。无法确认时标为“原型静态数据”或“当前未实现”。 |
| 边界与结果 | 成功、失败、无数据、权限或筹备中等可见结果；仅在原型存在这些状态时描述。 |

说明文字优先保留 PRD 原文中的功能解释，再补充从现有界面和交互代码可直接确认的事实。使用具体的组件名、字段名和状态名，避免“支持管理”“展示相关数据”这类空泛表述。

### 映射与覆盖规则

- 每张页面说明卡都必须绑定到一个真实的核心区域，使用清晰、稳定的 `data-*` 标识。
- 连线优先连接核心功能区；全局组件仅在其唯一说明卡上连线。
- 右侧说明按“全局功能（仅一次）→ 当前页面核心区域”的顺序排列，并使用连续编号。
- 需要展示完整说明时，右栏可滚动，但不能省略页面核心区域来迁就可视空间。
- 当项目已有页面实现时，以已有页面的组件、字段和交互为事实来源；PRD 与实现不一致时列出差异供用户审核，不擅自删除已有功能或虚构功能。

## 布局规范（严格执行）

### 整体结构

- **左右分栏布局**
  - 左侧：占页面宽度的80%-85%，展示产品主体界面内容
  - 右侧：占页面宽度的15%-20%，展示对应功能的详细说明文档
- **分隔线**：左右两栏之间有清晰的垂直分隔线
- **滚动同步**：左右两栏各自独立滚动，互不影响

### 连线功能（必须严格执行）

使用SVG技术绘制连线，确保连线清晰可见且不遮挡内容。

**连线规则：**
- 选择左侧界面中 2-4 个最重要的**当前页面核心功能区**增加连线指向右侧对应说明；全局组件只在其唯一说明卡上连线
- 禁止使用写死的固定坐标绘制连线。每条连线必须通过相同的 `data-proto-id` 绑定左侧组件和右侧说明框，并在绘制时实时读取两端元素的 `getBoundingClientRect()`
- 连线的**起始点**必须精确连接到左侧元素的右侧边缘中点
- 连线的**结束点**必须精确连接到右侧对应说明文字的左侧边缘中点
- 连线采用平滑的贝塞尔曲线，避免生硬的直角转弯
- 连线线条粗细为 2px
- SVG 连线层使用 `position: fixed; inset: 0; pointer-events: none;` 覆盖当前视口，坐标基于当前视口计算；不得把 SVG 放进任一滚动容器内部

**滚动与可见性：**
- 左侧主界面、右侧说明栏、页面窗口或任何承载原型主体的滚动容器滚动时，必须用 `requestAnimationFrame` 重新计算连线路径和编号位置，使连线跟随绑定组件/说明框一起移动
- 当左侧组件或右侧说明框任意一端离开其滚动容器的可视区域时，隐藏或不绘制对应连线与编号；两端重新进入可视区域后自动恢复
- 判断可见性时以元素所在滚动容器的可视矩形为准，至少检查 `top/bottom` 垂直交集；如存在横向滚动，也要检查 `left/right` 水平交集
- 弹窗打开/关闭、Tab 切换、筛选导致列表变化、说明内容展开收起、窗口 resize 后，都必须重新计算连线
- 使用节流函数统一调度重绘，例如 `scheduleDrawConnections()` 内部只保留一个待执行的 `requestAnimationFrame`，避免滚动时重复重绘

**交互效果：**
- 当鼠标悬停在左侧元素上时，对应的连线加粗并高亮显示
- 当鼠标悬停在右侧说明文字上时，对应的连线和左侧元素也会高亮显示

**连线标注：**
- 每条连线旁边添加小的数字编号，与右侧说明的编号对应

## 响应式设计规范

### PC端
- 保持上述左右分栏布局

### 手机端
- 自动切换为上下布局
- 上方展示产品主体界面，下方展示功能说明
- 连线功能自动隐藏
- 在每个元素下方直接显示简短说明
- 提供"切换视图"按钮，允许用户在"仅界面"和"界面+说明"之间切换

## 技术栈要求

1. **纯前端实现**：使用纯HTML、CSS和原生JavaScript，不依赖任何外部框架
2. **样式**：使用Tailwind CSS v3，通过CDN引入
3. **图标**：使用Font Awesome图标库，通过CDN引入
4. **代码结构**：
   - HTML结构语义化，使用适当的标签
   - CSS样式内联在`<style>`标签中
   - JavaScript代码内联在`<script>`标签中
   - 所有代码整合在一个HTML文件中，无需外部资源

## 样式与视觉规范

### 配色方案
- 如果用户指定了色系则用用户指定的色系，否则用下面默认的色系
- **主色调**：蓝色 `#165DFF`
- **辅助色**：浅灰色 `#F5F7FA`、深灰色 `#333333`
- **强调色**：绿色 `#00B42A`（成功状态）、红色 `#F53F3F`（错误状态）

### 其他样式要求
- 右侧的功能说明区要用琥珀色系，跟左侧内容区区分开！
- **字体**：系统默认无衬线字体
- **间距**：以 8px 为基本单位，保持一致的间距系统
- **阴影**：适当使用轻微阴影增强层次感
- **整体风格**：简洁、现代、专业的产品原型风格

## 输出要求

1. 输出完整的HTML文件代码
2. 代码开头添加简短说明，介绍原型的功能和使用方法
3. 确保所有连线的起始和指向位置完全正确
4. 确保在不同屏幕尺寸下都能正常显示和交互
5. 输出或保留一份“功能覆盖核对表”：逐页列出核心功能区，以及其组件/字段、操作逻辑、数据逻辑是否已写入说明；全局通用组件不得重复出现

## 注意事项

- 连线计算必须在DOM渲染完成后执行，使用 `DOMContentLoaded` 和 `resize` 事件重新计算
- 连线不得依赖初始渲染时的一次性固定坐标；必须在滚动、布局变化和内容显隐后重新读取绑定元素的位置
- 确保SVG的 `pointer-events-none` 不会阻挡下方元素的交互
- 移动端切换视图时，需要平滑过渡动画
- 所有元素ID和数据属性命名要清晰，便于连线脚本定位
- 在交付前逐页检查：每个页面是否至少有 2 个核心功能区说明；说明是否包含组件/字段、操作逻辑、数据逻辑；全局菜单、角色、通知是否只说明一次
